# 客户端纪律（`client/`）

> 本文件只在**处理 `client/` 下的文件时**加载。三分结构（core 共享核 + desktop 7777 + mobile 7778）与 2D 页面栈契约在根 `CLAUDE.md` 的「关键入口」，那是跨层的；这里放具体壳层的踩坑记录。

## 移动端操作层

- **左「开」右「做」（`client/mobile/src/MobileApp.tsx`，2026-07-28）**：**左**=摇杆 + 三个「缺角」角标（`CornerBadge`：外两边直线、朝摇杆那侧 1/4 圆弧，三个合起来把摇杆框住）——地图/背包/换装，**都是停下来看的东西**（后两者此前只有组件没有入口）；**右**=四键十字（`PadButton`：上=**创作**（弹出选单，2026-08-02 起：现只有「编辑此块」，未来创作类入口——沙盘触屏化、AI 生成——一律进这里，别再找槽位） · 左=视角 · 右=手电 · **下=JUMP**）——**都是移动中按的动作**。所以**角标在推摇杆时统一变灰、十字不变**（边走边跳是常态，边走边开背包不是），这条不对称就是左右分工的可见化。六条别改回去的结论：① **弧必须与摇杆同心**（圆心=摇杆中心，半径 = 65 + 对角 offset 的径向长度 7）——用角标自身尺寸当半径（试过 44）两条曲线会交叉而不是嵌套；只平移方框而不改半径，间隙会中间 7px、两端 0，像画歪了。② **只有画出来的 path 吃点击**（`pointer-events` 在 `<path>` 上、按钮盒子关掉）——角标方框必然压住摇杆圆环，不这么做就会**悄悄吃掉摇杆边缘的拖动区**（它是上面那层）；代价是角标几何中心落在缺口里，**e2e 必须按坐标点击**。③ **激活态只换颜色，不要旋转**——旋转既毁掉「这是哪个角」的语义，又把唯一可点的实心部分转到对角，第二次点击落进缺口静默失效（被 e2e 抓到，肉眼看不出）。④ 三个角标由**同一条 top-left path 镜像**得到（`-scale-x-100` / `rotate-180`）——避免三份手写路径各自漂移；摇杆的 `left/bottom/size` 与角标共用 `JOY_*` 常量，改摇杆位置不会让弧对不上。⑤ **角标不放图标、三个同色**：缺口的实心部分只有对角 ~24px，15px 的 emoji 塞满了还是一团糊色；三种颜色围着同一个控件像三件不相干的事在喊，**状态用浓淡（标量）不用色相（分类）**。⑥ 十字用**一个 `PAD_SPAN` 方框 + 四个绝对槽位**表达，不是四个各自定位的按钮——否则改一个尺寸就散架，且某个槽位空缺（编辑模式下上键让位给 edit bar）时会塌成另一种排布而不是留个豁口。e2e 断言的是**形状**（对臂共轴、四臂等距），不是四个坐标。⑦ **十字尺寸按左侧定，不按自身内容定**：摇杆+三角标占 140px 见方，十字 48px 键 → 152px，两个拇指视觉领地相当；初版 56px 键 → 180px，右半边看着比世界还重要。⑧ **材质是共用的一套**（`GLASS_FILL`/`GLASS_EDGE` + Joystick 内联样式）：顶部径向受光 + 上缘亮内阴影/下缘暗内阴影 + 真实投影。**平涂半透明 + 发丝边框在设计稿上没问题，铺到亮地面上就糊成一片**——摇杆的井要显得凹、球要显得鼓、十字要浮在世界之上，靠的就是这三件廉价的事。⑨ **左右各一块底盘，同材质同 `PLATE_PAD`**（左=圆角方、右=圆角十字，单条 path 不是两个交叉矩形——那样内凹处会露出两条边框接缝）：底盘留白是必需的，键贴着底盘边缘像贴纸不像模具。⑩ **角标是「边」不是「键」**：亮描边 + 极淡渐变。给它们套上和动作键一样的玻璃填充后，深色压深色**直接消失在底盘里**（只剩一根发丝）。⑪ **图标一律单色线条**（`ICON`/`LineIcon`，`currentColor` + 统一 1.8 描边）：**emoji 不能用**——它是另一套设计系统的彩色美术、各平台渲染不同、且 20px 下细节糊成一团（🔦 尤其）；文字标签（EDIT/3RD/JUMP）要语言、也表达不了状态。用 `currentColor` 的好处是手电点亮时**图标跟着键一起变琥珀**。
