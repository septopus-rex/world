# 引擎内部纪律（`engine/src`）

> 本文件只在**处理 `engine/` 下的文件时**加载。根 `CLAUDE.md` 保留跨层契约与选型口诀，具体的渲染/玩法踩坑记录在这里。
> 层级边界（Three.js 只允许在 `engine/src/render/` 内 import）仍在根文件，那是全仓纪律。

## 编辑 / Adjunct

- 编辑经 `EditSystem`（**palette 放置(add)** / select / move / set / delete / undo）→ `DraftStore`（write-behind 内存缓存 + IndexedDB 持久化，另有 `loadMeta/saveMeta` 世界级元数据通道存背包；启动时 `Engine.hydrateDrafts()` 注水，`ExportService` 提供 JSON 导出/导入）。
- **功能类 adjunct 是组合造型，不是单个盒子（2026-07-25）**：e4 book(封面/书脊/书页/两面烫金牌) · e5 board(木框/软木/图钉) · e1 link(边框/主面) · e3 video(边框/屏/电源灯) · e2 audio(音箱/纸盆/格栅)——**纯渲染层**，走 `AdjunctFactory` 早已存在的多部件路（一行 std → N 个子网格进同一个 mesh group）。三条铁律见 `plugins/adjunct/_shared.ts` 的 `composeParts`：**子件不带旋转**（行旋转由 mesh group 施加，再带一次就是双重旋转）· **部件必须留在 authored AABB 内**（碰撞体来自 std 行不是部件，越界就会穿墙）· **第 0 件是主面**（贴图/media 落在它上面，调用方与测试都按这个约定读）。契约测试 `unit/adjunct-shape.test.ts`。要更精细就换 a4 module 模型——但那要资产、且模型按 authored size 拉伸会变形，组合基元零资产且天然适配尺寸。
- **颜色 = raw 槽 3，一槽两通道**（`core/utils/Palette.ts`，规范 `protocol/cn|en/adjunct-types.md §2.3`）：`0`=该型默认色 · `1..255`=**内建 32 项调色板**（每项带 color + roughness/metalness，所以"选钢材"连金属度一起给了）· `≥256`=字面 `0xRRGGBB`。a1/a5/a6/a7 的槽 7 显式色仍优先；a2 槽 7 是贴图，故 a2 只能经槽 3 取色。**索引可改色、不可改义，只许追加**——2/3 号 2026-07-25 从纯 `#3366ff`/`#ff0000` 调成颜料饱和度，一次性把所有既有场景（含 motif 生成物）从"玩具积木"拉回材质感，且没动一个字节数据。
- **Septopus 动画协议**（`AnimationSystem`，规范 `protocol/cn|en/animation.md`）：timeline 步驱动 move/rotate/scale/opacity/color/texture(UV 滚动)/morph(blendshape)；非 transform 覆盖由 `VisualSyncSystem` 经 `RenderEngine.updateObjectAppearance/setTextureOffset/setMorphInfluences` 落到 handle。**几何基元**见 `protocol/cn|en/adjunct.md §6`（box/sphere/cylinder/cone/plane/grid/tube/wedge；**wedge 必须与 `MovementCollider.topYAt` 同一平面方程**）。
- **背包/物品**（规格 `docs/plan/specs/inventory-local-first.md`，实例规范 `protocol/cn|en/item.md`）：`ItemRegistry`（模板 + seed 确定性推导属性）→ b5 adjunct → `ItemSystem` **原子**拾取/丢弃（背包变更 + block raw 重序列化进 draft 同帧完成）。trigger 动作经 `world.actuator`（`IActuator`/`LocalActuator`，可注入）执行，动作面 adjunct/flag/bag/player/sound/system + `delay`/`spawn`/`despawn` + `damage`/`projectile` 共 **11 种**（bag·player·damage·projectile 仅 Game 模式），JSONLogic 条件可读 `inventory.*`；player 方法含 setSpawn/enterGame/exitGame/damage/heal/**teleport**（锚点制，任意模式，见 `specs/teleport-portal.md`）。
- **原生在场游戏（Pattern B）**：`PoolSystem`/`MahjongSystem`/`ShootingRangeSystem`/`TumbleSystem`——System 持逻辑、棋子即 adjunct 实体、点击经 `interact.primary` 触发动作。**生命周期区域门控**：`configure` 只登记(arm)，每帧 `syncSession` 按「`mode===Game` 且本块＝`world.activeGameBlock`」spawn/teardown，走出 block 即拆局（街机柜模型，无中途存档）；游戏富声明在 **game trigger**（`b8`+`enterGame` 带 `exitPolicy` 三档），`block.game=1` 只是粗粒度"此处可玩"门控位。**Tumble = 首个真实刚体物理**：`@dimforge/rapier3d-compat`（headless WASM，落在 `core/`），每局独立 scoped rapier world，逐帧把 body 位姿写回 `TransformComponent`（**倒塌必须同步旋转**，pool 只同步位置）。以上细节与踩过的坑（rapier 睡眠体须 `wakeUp()`、`setEntityColor` 要等 mesh 出现、yaw=90° 万向锁）见 `docs/plan/specs/native-in-world-games.md`。**运行时改色**经 `core/utils/Appearance.ts setEntityColor`（clone-on-write 隔离材质，不染共享材质邻居）。
- **出生防卡死**：落入固体内时 `MovementCollider.popOutIfEmbedded` 自动弹上固体顶面（行走子步 ≤0.08m < 0.1 触发余量，正常移动永不误触）。
- **事件队列**（`core/events/`，设计 `docs/plan/specs/event-bus-design.md`）：`world.events` 帧作用域双缓冲队列——emit 不跑回调、系统拉 reader、边界回调仅在 step 尾按 (frame,seq) 全序派发。旧总线仅余 `player:*` 生命周期与 `audio:played`；Engine 门面双总线订阅 + LEGACY_EVENT_MAP 别名（dev 告警一次）。
- **编辑器创作闭环**：Edit 模式左侧 palette（`core/edit/AdjunctDefaults.ts` 给默认 raw；module 按 `world.moduleCatalog` 每模型一钮；track 不入 palette，coaster 走关卡 JSON），点击表面放置（`EditTask 'add'` → `spawnAdjunct` 复用），undo=删除。**第二排是组合件 prefab**（`⬚ 名字 (件数)`，从 `listPrefabs()` 读活库，不是硬编码菜单）：点击盖章 → **N 个普通 authored adjunct**（单位立方站在点击点上，点击点=底面中心），**不标 `derivedFrom`**——盖出去的东西从此归作者，改库不会回溯改它（取舍见 `spp-editors.md §9.4`）。两条纪律：**一次点击 = 一步撤销**（`HistoryEntry.also[]`，别退化成按 12 次 Ctrl+Z 看长椅一件件拆开）· **`block.max` 按整件校验**（`hasRoomFor(n)`，半张长椅比没有长椅更糟）。**移动平台跟随**：玩家脚下支撑 solid 的帧位移传递；solid 缓存每帧原地刷新位置（否则触发器移动后碰撞箱滞留旧位姿）。
- **弦粒子 SPP**（完整协议已落地，规格 `docs/plan/specs/spp-protocol-full.md`）：b6 raw `[origin, cells, theme]` → `core/spp/Expander.ts` 纯递归展开 → BlockSystem 产出**独立标准 adjunct 实体**（碰撞/触发器/LOD 原生）；derived 带 `derivedFrom`，`BlockSerializer` 只留 b6 源行。四项能力：叠加态确定性**坍缩**（mulberry32，seed=块+cell+面）· `refinement` 递归细化 · theme=**StylePack**（数据化可 CID/URL，`world.styleOverride` 秒换风格）· **L2 二进制**（`CollapseCodec` + `core/spp/SppL2.ts` 桥）。注意 `a1` 墙无贴图槽，**贴图墙体必须走 `parts` 组合发 a2+贴图槽**（terran 风格包即此，texture.md §8）。**StylePack 还带第三个池 `prefabs`（组合件，2026-08-14，`spp-editors.md §9`）**：同一套 `parts` 词汇、不属于任何面，帧 = 胞的 Bottom 面帧（`u→X 东 · v→Y 北` 地面足迹，`w/sw→Z 上` 离地/自身高度），`expandPrefab` 复用同一个 `partToBox`——**面 option 与组合件必须走同一段几何代码**，否则编辑器能显示世界放不出来的东西。引用只有 `pack#key` 一种形态（§3.6 一出生就守住，无下标可漂移）；守卫 `checkPrefab` **不跑 `part-too-deep`**——那条把 option 读作贴面的皮，而组合件按定义是体，全高衣柜是常态不是错误。

## 渲染与画面

- **相机**：硬着陆按落差触发抖屏 + 下沉（`_camShake` 衰减包络，仅叠加到相机、不污染玩家 transform）；**一/三人称切换是推轨不是硬切**，且 **observe 轨道锚点有意不跟随眼高修正**——两条都见 `docs/systems/player.md §3`（回归测试 `engine/tests/systems/camera-rig.test.ts`）。
- **画面基线（2026-07-25 一次性调校，别再各处加光）**：ACES filmic tone mapping（exposure 1.0）+ `render/SkyEnvironment.ts`（渐变天空 canvas → `scene.background`，同一张图过 PMREM → `scene.environment` 做 IBL，雾色恒等于地平线色）+ 材质默认 `roughness 0.85 / metalness 0`。**光比是配过的一组数，动一个就得重看**：sun 1.9 · ambient 0.05 · hemisphere 0.06 · `environmentIntensity 0.32`——IBL 是补光、太阳是主光；实测把 ambient 提回 0.14 或 IBL 提到 0.5 会立刻回到"纸片感"（曝白、明暗面等亮）。
- **贴图表面细节（2026-07-26）**：`render/SurfaceDetail.ts` 经 `onBeforeCompile` 往标准材质注两层——**macro** = 世界坐标低频 fbm 调制明度 + 色温（暗处偏冷/亮处偏暖）；**detile** = 同图第二次旋转 37° 采样后按噪声掩码混合（旋转保纹素密度、只打散相位；不用 Heitz-Neyret 六边形是因为那需要 `textureGrad`，GLSL ES 1.0 下要靠扩展，而两次连续采样零伪影且少一次取样）。三条实测结论**别凭直觉改回去**：① **只给大表面**（最大面 ≥12 m² 才 macro，≥8 m 见方且扁才 detile）——世界噪声会把 1 m 的箱子**整体**染色，变成一堆随机深浅的盒子，比原问题更糟；② **fbm 后的对比拉伸 `(m-0.5)*2.5+0.5` 是必需的**——多倍频叠加向 0.5 集中（中心极限），不拉伸时 0.18 的强度到画面上只剩 6%，肉眼为零；③ 掠射角 + 雾下几乎无效，收益在中距主视角。契约测试 `unit/surface-detail.test.ts`（钉 three 的 chunk 锚点，升级改名即红）+ `e2e/surface-detail.spec.ts`（真实 GL 编译——GLSL 语法错在 node 里是静默的）。同期地面贴图纹素密度 `size 0.25 → 0.5`（对齐其余贴图的 256 px/m）。**下一个瓶颈是法线贴图**：地面至今完全不吃光照方向，且两张 ground-*.png 只有 128²（其余贴图均 512²）。
- **「天一直黑着」不是 bug,是节奏(2026-07-29 实测,别再重查一遍)**：逐小时采 `dayFactor` 得 `[0×6, 0.58(6时), 1×11, 0.42(18时), 0×5]`——**夜占 12/24 小时,其中 11 小时 dayF 严格 = 0**(不是"暗",是常量平台期,画面上毫无变化),晨昏各只有约 1 小时。默认 `localDaySeconds=600` ⇒ **连续 4.6 现实分钟纯黑**,玩家读作"卡住了"。循环本身是好的(`integration/day-night-cycle.test.ts` 断言最暗点之后光一定回来)。真要缓解,旋钮是 `DAYLIGHT.twilight`(晨昏带半宽,0.12 ⇒ ±6.9° ⇒ 平台期长)或 `localDaySeconds`,**不要去抬 `ambNight`/`sunNight`**——那是画面基线,一动整场变纸片。另:`World.runLoop` 的 dt 取真实帧间隔但**钳在 0.1 s**,故低帧率下仿真时间比现实慢(e2e 软渲染只有真机的 1/3),这是防后台标签页大跳的必要设计,别当成时钟 bug。观测入口 `Engine.environmentInfo()`(hour/weather/**dayFactor**),双端 HUD 已显示(桌面罗盘中心 · 移动 MiniCompass 块)。
- **昼夜与天气**：`EnvironmentSystem.DAYLIGHT` 晨昏带 smoothstep 渐变（天空/IBL/日照三者吃同一个 dayF）；雷雨按 grade 缩放的确定性定时器触发全场闪光。**日内时钟与链历法是拆开的**：太阳时/分/秒由本地 dt 连续推进，链高度只跳"日历日期"这个整数——理由见 `protocol/cn|en/world.md §3.1/§3.2`（若让链高度驱动时分秒，「1 区块=1 天」会使其恒为零、太阳冻结）。
- **天气→光照只有一条通道：`EnvironmentSystem.OVERCAST` 的单个标量 `oc∈[0,1]`（2026-07-28）**，由 (category, grade) 查表得出，**`clear` 必须恒等于 0**——画面基线那组光比才能原样保留、晴天时整个特性是惰性的。**但一个标量必须驱动四个目标，只乘太阳是错的**：只调暗太阳得到的是「有蓝天和硬阴影的暗场景」＝黄昏，不是暴雨。四项：① 太阳 ×(1−0.92·oc)（直射光近乎消失，**硬阴影因此自己淡掉，不需要动阴影代码**）· ② ambient +0.06·oc、IBL ×(1+0.8·oc)（光变成无方向的，阴天是"平"不是单纯"暗"）· ③ **天空去饱和+压暗**（`SkyEnvironment.overcastStop`，朝自身 luma 混而非固定灰——固定灰会把夜晚照亮）· ④ 雾 `near` 收紧、**`far` 绝不动**（那是 `streamingReach`，一动流式窗口边界就又露出来）。天气切换走与太阳同一条 `chase` 包络，否则块 tick 会让整场曝光单帧跳变。回归 `systems/weather-lighting.test.ts` + `e2e/weather-lighting.spec.ts`。
- **`scene.background` 用 equirect 纹理时，改了 canvas 必须 `texture.dispose()`（2026-07-28，血的教训）**：three 把 equirect 背景转成 cubemap **缓存在 WeakMap 里、只认 `dispose` 事件、完全不看 version**（`WebGLEnvironments.getCube`）。所以 `paint()`+`needsUpdate` 只更新了 2D 上传，**可见天空纹丝不动**——2026-07-25 到 07-28 之间，昼夜循环一直在改灯光/雾色/IBL，而**天空自始至终是第一帧烘出来的一张静态图**，`skyInfo().horizon` 报的灰色屏幕上根本没出现过。**node 里测不出来（bug 在 GPU 侧缓存）**，只能靠 `e2e/weather-lighting.spec.ts` 的像素回读；`skyInfo().epoch` 是"天空真的重新发布了"的可观测证据。
- **雨雪粒子（`render/ParticleFX.ts`，2026-07-27 重写）**：四条铁律，任一条破了就退回"一堆小方块糊在脸上"——① **点精灵必须带 `map`**：无贴图的 `PointsMaterial` 画出来就是不透明**正方形**（这正是旧版下雨的真身），两张 sprite 由 `DataTexture` 程序化生成（雨=竖条纹、雪=柔圆点；不用 canvas 是为了 headless 也能单测）；② **粒子要真的下落**：旧版只把整盒重新居中到玩家身上、位置数组从不积分，等于一团静止方块焊在相机上；③ **坐标是盒内局部 + 每帧减去锚点位移**——存绝对坐标会让 32 km 外的雨落在 4 mm 量化格上（FloatingOrigin 存在的理由），不减位移则整场雨随人平移、视差消失（传送用取模回绕，一帧到位）；④ **alpha 走 vec4 顶点色**（three 的 `USE_COLOR_ALPHA` 需要 `color` 属性 itemSize=4），近端 0.8→4 m 淡入把糊脸的大精灵消掉、远端在盒面(span/2)**之前**淡尽，方盒边界才不会显形。密度按视锥算不按总数算：pool 9000 / span 34 m 下 grade 3 视野内约 350 粒（4000/44 m 的初版只有 ~20 粒，暴雨看着像毛毛雨）；CPU 0.14 ms/帧，clear/cloud 直接 return。`weatherGrade` 缩放粒子数与落速，**snow 与 rain 都要驱动**（旧版只判 `isRaining`，四分之一的天气周期什么都不画）。回归 `unit/particle-weather.test.ts` + `e2e/weather-particles.spec.ts`（真实 GL：alpha 顶点色走的是另一条 shader 程序路径，编译错在 node 里静默）。
- **玩家自带照明：角色补光 + 手电筒（`render/PlayerLighting.ts`，2026-07-28）**：夜间基线（sun 0.15 / ambient 0.02）是**真的夜**，黑到看不见自己的 avatar。**修法不是抬全局 ambient**（那是唯一会把整个画面压平的旋钮，画面基线正是为了摆脱"纸片感"才调低它的），而是给玩家两盏跟着走的灯：① **fill**（PointLight，夜间 45 cd）· ② **手电筒**（SpotLight，从相机打出，`Engine.setFlashlight/toggleFlashlight`，双端都有按钮：移动端在**右侧四键十字的右键**，桌面在 ActionRail）。三条实测结论：**① 灯不能放正上方**——人的正/背面是竖直面，顶光入射 ~90°，N·L 塌成 0，实测 avatar 亮度只从 luma 1.1 升到 4.0，等于没开；改成世界固定的斜上方偏移 (2.2, 3.2, 2.2) 后 45° 入射，同样强度立刻可读。**② 也不能挂在相机上**——那样地面光斑会随视角旋转，看着像世界在转。**③ 强度只能靠像素定**：12 cd → luma 16（仍看不清）· 60 cd → avatar 亮得像白天贴在黑背景上 · **45 cd → luma 30**（看得清且仍是夜）。fill 由 `1−dayF` 驱动，**正午必须恰好为 0**（同 overcast 的 `clear→0` 纪律）；手电筒与昼夜无关（洞里白天也要用）。回归 `systems/player-lighting.test.ts` + `e2e/player-lighting.spec.ts`（真实 GL 像素回读）。**e2e 采像素前必须先 `#init-loader` 移除 + `render()` 两次**——启动遮罩是覆盖全屏的半透明黑，而单次 out-of-rAF render 读回的是上一帧，两个坑都曾让"补光无效"的结论完全反过来。
- **e4 书名印在封面上,不浮在头顶（2026-07-29）**：书的标题走 `plate` 指令(`PlateConfig` → `composeParts` → `AdjunctFactory` → `MediaScreens.attachTextPlate`)烫在**两块封面书名牌**上,e4 已移出 `AdjunctSystem` 的 `LABELED` 集合。三条别推翻的结论:① **底色必须是浅的**——直觉配色是深皮革烫金字,但**封面是竖直面**,正午太阳掠射、几乎只吃 0.32 的 IBL,实测深底金字整块牌子 luma 只有 **1.3/255**(黑矩形),换象牙底深字后 11.1 且夜里同样成立;**可读性来自底色接到的光,笔画是做减法**。② **字号是解出来的不是定的**,且解法不是「字号从大往小试贪心换行」——贪心把第一行塞满、字号被那行钉死(实测 31px vs 45px);正解是**对每个行数二分「最窄的均衡行宽」再反解字号**(`layoutPlateText`)。③ **二分下界必须是「最宽的词」而不是「最宽的字」**——否则求解器会靠**词内断行**换来 3% 的宽度:「八爪印记 · 残卷」拆成「八爪印/记 · 残卷」,在书封面上读起来就是错字。回归 `unit/text-plate.test.ts`(纯排版,注入 measure,含全部在库标题)+ `e2e/book-cover-title.spec.ts`(真实 GL:canvas 内容 + 掉 map 前后的像素结构差 —— **判据用「笔画带来的方差」而不是亮度差**,牌子太暗时亮度说明不了任何事)。
